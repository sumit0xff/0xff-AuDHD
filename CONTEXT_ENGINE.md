# 0xff Context Engine

The Context Engine bridges the gap between raw repository analysis and the specific intent of a user's prompt. It transforms the Knowledge Graph generated by the Project Analyzer into a highly structured, token-optimized context payload for AI models.

---

## Purpose

Context quality matters far more than context quantity. Modern LLMs boast massive context windows (upwards of 2M tokens), which creates a dangerous temptation to blindly dump the entire repository into every prompt. 

However, LLMs suffer from "lost in the middle" syndrome. If you feed an AI 500 files, it loses focus on the architectural constraints and hallucinates solutions. Poor context leads directly to duplicated utility functions, inconsistent styling, broken architectural boundaries, and bloated generation. 

The Context Engine curates the data, ensuring the AI receives exactly the information it needs to solve the immediate problem—and absolutely nothing else.

---

## Responsibilities

The Context Engine must:

- **Build repository summaries:** Distill the entire codebase into a lightweight, high-level overview.
- **Generate task-specific context:** Understand the intent of the user's prompt and fetch only the relevant subset of the Knowledge Graph.
- **Select only relevant files:** Prune the dependency tree to exclude boilerplate and unrelated modules.
- **Reduce token usage:** Strip out minified code, massive JSON blobs, and irrelevant comments to save bandwidth and API costs.
- **Preserve architectural understanding:** Ensure the AI knows *how* the selected files fit into the broader system, even if the whole system isn't provided.
- **Highlight reusable code:** Actively surface existing utilities, components, and types to prevent the AI from reinventing them.
- **Explain important relationships:** Clearly articulate how component A talks to service B.
- **Inject 0xff Rules:** Automatically append the relevant 0xff Engineering Principles (from the Rules Engine) into the final payload.

---

## Context Pipeline

The engine operates as a funnel, filtering massive amounts of data down to a laser-focused prompt string.

1. **Repository Analysis:** Invokes the Project Analyzer to scan the raw filesystem.
2. **Knowledge Graph Generation:** Receives the structural map (ASTs, dependencies, frameworks) from the Analyzer.
3. **Task Understanding:** Parses the user's prompt (e.g., "Fix the login bug") to identify entities, keywords, and intent.
4. **Relevant File Selection:** Queries the Knowledge Graph to find the entry points (e.g., `Login.tsx`, `authService.ts`).
5. **Relationship Extraction:** Traverses the graph outward from the entry points to gather necessary dependencies (e.g., `Button.tsx`, `AuthContext.ts`).
6. **Context Compression:** Strips out irrelevant methods, truncates massive files, and removes `.test.ts` files unless the task explicitly asks for tests.
7. **Structured Context Compilation:** Formats the remaining data into a standardized Markdown or JSON payload injected into the final LLM prompt.

## Context Types

Depending on the user's task, the engine generates different flavors of context.

- **Repository Overview:** A high-level map of the codebase. Used when the AI is asked a broad architectural question (e.g., "Where is authentication handled?").
- **Feature Context:** Gathers vertical slices of the app (UI component + Service + API Route + DB Schema) required to build a new feature.
- **Bug Fix Context:** Focuses heavily on the specific file, its immediate caller, and recent git diffs to isolate where a regression occurred.
- **Component Context:** Pulls the UI file, its styling module (CSS/Tailwind), and shared UI types, while ignoring backend services.
- **API Context:** Focuses on routing, middleware, controllers, and data validation schemas (Zod/Joi).
- **Database Context:** Focuses purely on ORM models (Prisma/TypeORM), migrations, and seed files.
- **Architecture Context:** Provides only interface definitions, abstract classes, and folder boundaries, omitting implementation details.
- **Dependency Context:** Extracts the `package.json` and lockfiles to answer questions about external library usage and versioning.

## Relevance Ranking

When the user asks a question, the Context Engine must rank the thousands of files in the repository to pick the top 5–10 most relevant ones. It scores files based on:

- **Lexical Match:** Does the filename or file content match keywords in the user's prompt?
- **Import Relationships:** If `A` is highly relevant, `B` (which is imported by `A`) gets a relevance boost.
- **Call Hierarchy:** Is the function mentioned in the prompt called heavily by a specific service?
- **Similar Functionality:** If the task is "Create a DatePicker," the engine highly ranks existing files in the `components/ui/` folder.
- **Shared Dependencies:** Files that share the same obscure npm package might be related.
- **Framework Conventions:** If the user mentions "routing" in Next.js, `page.tsx` and `layout.tsx` files receive a massive boost.
- **Recent Modifications:** Files modified in the uncommitted git tree or recent commits are exponentially more likely to be relevant to a current task.
- **Centrality (PageRank-style):** Files that are imported by hundreds of other files (e.g., `utils/logger.ts`) are flagged as "Shared Utilities" and are always referenced.

## Context Format

The final output is injected into the LLM system prompt in a strictly formatted structure.

```markdown
# Project Summary
A Next.js e-commerce storefront utilizing Tailwind CSS and Prisma.

# Relevant Files
- `src/app/login/page.tsx` (Entry point)
- `src/lib/auth.ts` (Core logic)
- `src/components/ui/Button.tsx` (Shared component)

# Architecture Notes
This project uses Server Actions for mutations. Do not use standard API routes (`/api/...`) for the login flow.

# Reusable Components
- Found `src/utils/validators.ts`. Use `isValidEmail()` instead of writing a new regex.

# Existing Patterns
State is managed locally via React hooks; no Redux is present.

# Potential Risks
Modifying `src/lib/auth.ts` will impact 14 other routes. Proceed with caution.

# Recommendations
Extend the existing `AuthError` class rather than creating a new error type.

# Confidence Score
94% relevance match for "login bug".
```

## Design Principles

- **Fast:** Must generate context in under 100ms.
- **Deterministic:** The same prompt against the same repo state must yield the exact same context payload.
- **Explainable:** The engine must be able to tell the user *why* it included a specific file in the prompt.
- **Framework Agnostic:** Relies on the Knowledge Graph, not hardcoded framework rules.
- **Offline First:** Does not require an API to rank, compress, or generate the context payload.
- **Token Efficient:** Every character is aggressively optimized to keep LLM context windows small, fast, and cheap.
